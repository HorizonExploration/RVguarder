# M1 执行前快照证明

## 本轮实现

`spec/execution_proposals.py` 新增严格类型的 `proposed_content_use` / `snapshot-v1` 证明。它绑定已固定的实际字节版本、接收方、原参数哈希、具体工具及有限操作族、任务、认证主体、Agent、session/run/call和五分钟期限。完整资源最大 1 MiB；不声明工具成功、不提供公开分类、不签发授权。

三个实际 Node 办公工具使用宿主私有密钥签名已准备的快照。生成的 Guard Hook 只从同进程宿主 registry 获取有界证明，不读取 Agent 参数中的同名对象。缺失、异常或超限证明均不构造阻断或放行。后端离线时不查询该 registry，所有工具透传契约保持。

后台 bridge 冻结证明、原参数和认证上下文后排队；数据库、签名、唯一活动任务与精确授权核验都在 worker 中执行。当前查询结果明确为 **`decision_eligible=false`**；仍不能用于授权豁免或降低 RV/PMKB 裁决。任务及授权最终匹配采用同一次当前记录读取，防止两次查询间新增歧义任务。

快照准备、观察记录和签名统一解析 SDK 身份；event/context 的 Agent/session 或 run/call 冲突会失效，而非任选一个字段。生成 Hook 优先采用 SDK ctx 身份，保留旧事件字段兼容。

## RV 独立阻断保持

新测试使用实际默认 DSL 和真实成功历史，给定单步策略为 `allow`、`ask`，即使存在精确匹配的快照授权诊断，RV preview 与实际 pipeline overlay仍返回 `block`，引用原历史且无降级原因。生成的 Node Hook 也保留后端明确 block。

这些是组件回归：单步策略输入及成功历史为受控测试夹具，HTTP为 mock，不能声称取得新的原生攻击阻止成绩。本轮旧67条规则文件不变，没有全局RV门或授权豁免。
