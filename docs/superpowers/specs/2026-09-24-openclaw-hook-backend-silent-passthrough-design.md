# Guard 后端不可达时的 OpenClaw Hook 静默透传设计

## 目的与确认的行为边界

用户要求：Guard 后端未启动、停止或不可达时，已安装的插件不得影响**任何** OpenClaw Agent 的行为，写入与执行类工具也必须如此。后端可用时，插件仍应按正常 Guard 决策返回 `allow`、OpenClaw 原生审批或 `block`。OpenClaw 自身的权限、审批及工具执行机制不属于本插件，继续独立生效。

本设计把后端不可达解释为插件无法与 Guard 后端建立或维持通信的传输故障：连接拒绝、网络错误、请求超时、健康检查无响应。收到有效 HTTP 响应的鉴权失败、请求校验失败、业务错误和正常 Guard 决策不属于“静默”。插件不得把这些响应伪装成后端停机：Guard 明确返回非 2xx 时维持 `active`，该次调用沿用当前分级错误策略（低影响工具透传，高影响工具阻断；遗留 `failClosed=true` 对此类**有响应**错误仍可全量阻断），并记录脱敏错误。健康接口返回非 2xx 也证明传输可达，但不代表防护正常，状态须显示为“后端响应异常”而不是“静默不可达”。

这是可用性优先的 **fail-open** 策略。静默期间 Guard 的安全监视、阻断、审批与审计回传暂停；因此实验不能把这段时间的攻击未达归功于 Guard，也不能声称后端失联仍有防护。

## 状态与数据流

插件决策状态为 `silent`、`active` 两态，另有不改变决策的诊断标志 `backend_response_error`。进程启动时为 `silent`，立即在后台发起健康检查；首次成功即可进入 `active`。健康接口明确返回非 2xx 时说明传输可达，也进入 `active`，但置 `backend_response_error=true`，随后工具调用按有响应错误的分级策略处理；状态不能宣称保护正常。在 `silent` 时，`before_tool_call` 对任何工具和任何 Agent 返回 `undefined`，不发起同步 Guard 决策请求；`after_tool_call` 不等待 Guard 回调；既有审批回调若因后端失联而触发，不应额外延迟 OpenClaw 的审批结果。插件可以在后台记录本地、脱敏的状态日志，并继续健康探测。

在 `active` 时仍走现有 Guard Hook 决策。若 `before_tool_call` 的后端请求发生传输故障，当次调用返回 `undefined`，状态立即变为 `silent`，后续工具调用无须等待再次失败。`after_tool_call` 或审批结果同步出现传输故障也应触发 `silent`，但不得反向改变已由 OpenClaw 执行的动作。失联后的健康检查连续成功达到恢复条件，才清除恢复中诊断并恢复“防护正常”状态；一个非 2xx 健康响应虽结束传输静默，却不能计作成功恢复。恢复不重放静默期间错过的阻断或审批。

后台健康检查不得阻塞任何工具调用。即便已处于 `active`，后端在上次健康检查后突然断开时，首个受影响的 Hook 调用仍可能等待一次有界的连接/决策超时；这是无法在同步拦截架构中完全消除的竞态。验收上限沿用当前 `decisionTimeoutMs` 默认 2000 ms；此后必须保持静默透传，不对每个工具重复支付该超时。初始启动只需一次成功健康检查；失联后的恢复保留两次连续成功的门槛，避免抖动。插件状态和日志应能区分 `silent`、`active` 与“后端有响应但报错”，以便使用者知道 Guard 保护是否暂停或异常。日志不得包含原始命令、消息正文或凭据。

## 配置兼容

旧配置 `failClosed=true` 曾在 Guard 不可达时强制阻断全部工具，直接违背本次全局要求。升级后，传输不可达时静默透传优先，不能被 `failClosed`、高影响工具分类或旧分级故障逻辑覆盖。生成配置不再把 `failClosed` 表述为可控制后端故障时的阻断；对已有配置保留解析兼容并给出脱敏的弃用提示。不得为某个 Agent、工具名或调用参数设置静默例外。

该兼容性变更必须在 README、`AGENTS.md` 的架构约定、Hook 文档、状态接口说明和旧故障策略说明中显式标出。状态查询的 fallback 不得在未知配置时猜测 `failClosed=true` 或暗示仍会阻断。`circuitOpen` 可继续作为诊断字段，但它不能成为继续拦截或重新请求 Guard 的理由；状态语义应与实际透传行为一致。

## 实现边界

改动落在生成的 OpenClaw Hook 插件及相关配置、文档和测试。`openclaw_guard/integrations/hook_runtime.py` 的 `_plugin_source` 是运行时代码的唯一事实来源；不得引入真实后端运行依赖或要求修改 OpenClaw 内核。现有服务器侧 PMKB/RV/审批策略保持不变。

健康检查只可调用本地配置的 Guard 健康接口；端到端测试使用内存中的 `fetch` 桩和生成插件的 Node 执行环境，不连接真实网络，不执行真实工具或 shell。若 Node 不可用，测试可跳过 Node 行为部分，但源码断言不能替代已执行的行为测试结论。

## 验收矩阵

| 后端状态 | 读 | 写 | 执行 | after Hook | Guard 保护状态 |
| --- | --- | --- | --- | --- | --- |
| 启动尚未确认健康 | 透传 | 透传 | 透传 | 不等待 Guard | 暂停 |
| 不可达／传输超时 | 透传 | 透传 | 透传 | 不等待 Guard | 暂停 |
| 后端恢复且健康确认 | 正常 Guard 决策 | 正常 Guard 决策 | 正常 Guard 决策 | 正常回传 | 启用 |
| 后端明确返回 `block` / `require_approval` | 按结果 | 按结果 | 按结果 | 按现有生命周期 | 启用 |
| 后端可响应但返回 401／4xx／5xx | 不误判为静默；放行 | 同左 | 同左 | 不覆盖工具既成结果 | 异常，非静默 |

> 2026-09-30 修订：有响应的错误不再走“分级错误策略”。插件升级为严格 fail-open——后端明确返回 401/4xx/5xx，或返回 2xx 但响应体不可解析时，`before_tool_call` 一律返回 `undefined`，不为任何工具（含写入与执行）构造阻断；错误只体现为 `backend_response_error` 诊断标志。只有 Guard 明确返回 `action: "block"` 才阻断；遗留 `failClosed` 不再阻断任何调用。本文件上文“高影响工具阻断”“沿用当前分级错误策略”等表述已过期，现行契约见 [Hook 运行时](../features/runtime-hook.md)。

测试需覆盖所有 Agent 标识、`failClosed=true` 遗留配置、启动前首个工具调用、一次故障后的连续多次调用、恢复、`before`/`after`/审批同步三条路径、有效 Guard block 不被透传、HTTP 错误不被伪装成停机，以及无真实副作用。尤其要证明生成插件在后端不可达时对写入、执行返回 `undefined`，而不是 `{block: true}` 或新的 `requireApproval`。

## 与 office_value 实验的关系

此行为是产品可用性前提，不是办公场景安全拦截率的分母。后续 `office_value` 可增设独立的“后端静默非干扰”测试臂：同一声明式读、写、执行轨迹比较无插件与已安装但后端静默的插件，结果应一致；该臂只展示插件故障时不会阻碍办公任务，不计入 PMKB/RV 成功拦截。已有 v3-foundation 结果保持不变，不以新故障策略回写历史证据。

## 不在范围

不改变后端可用时的安全规则，不新增实际 shell、网络、办公 SDK 或真实凭据操作，不保证静默期间任何安全拦截，也不声称所有可能的网络故障在首次调用上可实现零延迟。
