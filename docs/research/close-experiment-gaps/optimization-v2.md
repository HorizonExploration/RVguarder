# 未通过原因与下一轮优化

## 判定与原始证据

原 Q5 的安全收益与正常任务保留部分满足本轮判据；整体未通过的直接原因是正常新增提示 **16>5**、回调 p95 增量 **381.349>50 ms**。完整 SDK 调度边界仍未核验。另有7例攻击后果未防止，属于需改进的覆盖缺口，但原Q5没有要求15例攻击全部阻断。历史结论保持不变。

[逐动作诊断](m3-failure-diagnosis-v1.json)复算冻结原始数据，不修改规则或增加安全分母。

## 已实施：减少重复同步持久化

`_replace_action`本身已经同步落盘，Hook又调用`_save_all`造成重复整表序列化。删除两处重复写入，保留返回前持久提交、动作事件序号、审计顺序及独立block。

30次隔离本地read调用：写盘150→90次，本次p95约45.97→39.95ms。[优化前](hook-persistence-before-v1.json)、[优化后](hook-persistence-after-v1.json)分别记录源码哈希与逐调用数据。单次样本不证明稳定提速比例，更不证明SDK/Q5时延通过。

定向回归67项、4个子测试通过，覆盖allow/ask/block落盘与重新加载、审批同步、RV授权与跨会话阻断、故障透传。当前代码比v3候选新增此修复；v3的交付验收不认证这次变化，重新打包须在本阶段收敛后进行。

## 升级顺序与验收

1. **一般效果契约。** 有界识别解释器删除/写入/外发能力；补全调度权限模型。每个真实工具调用仍只有一个`tool-call-v1`。用不同语法合法对照与绕过负例验收，未知语法不自动批准。
2. **可信授权贯通。** PMKB在决策时接收受控宿主事实，限定任务、操作、参数摘要、资源版本、接收方、有效期及撤销；执行器消费单次许可。不得把附件声明、public命名或模型判断当授权，不能全局降低RV block。
3. **性能定位。** 同一调用记录决策、准备、持久化、审计、序列化与HTTP，先做短原生probe。缓存只读编译产物并绑定策略版本；不缓存可撤销的授权裁决，不异步丢弃安全历史。
4. **补齐归因门。** 权限关系消融关闭策略图、生成关系监视器、主体图全部路径，保留DSL；审批复用必须出现实际eligible和allow-always，且验证关闭后不提交不复用。
5. **阶段收敛后再冻结。** 已揭盲失败只作后续calibration。先定向验收；仅在需要新的整体优越性结论时建立新holdout，不反复运行旧矩阵冒充盲测。

默认67条规约、历史r4及原始证据保持不变。升级候选另存，门未通过保持`release_qualified=false`。
