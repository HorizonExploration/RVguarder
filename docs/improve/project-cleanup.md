# 项目清理与优化记录

## 1. 本次目标

本次优化聚焦四类工作：

- 清理明确无用的遗留模块与构建产物
- 收敛项目结构与文档导航
- 输出项目级分析与结构清单
- 给出不破坏主链的后续重构建议

## 2. 已完成的清理动作

### 2.1 删除未接入的数据库迁移目录

已删除：

- `migrations/`

删除原因：

- 运行链中没有任何 Python 模块引用该目录
- 目录内仅包含占位 `__init__.py` 和一份独立 SQL
- SQL 头部还引用了并不存在的 `migrations.migrate_001`
- 当前 PostgreSQL 方案实际由 `openclaw_guard/db_store.py` 直接负责建表与运行，不依赖单独迁移器

影响评估：

- 不影响 SQLite 默认模式
- 不影响 PostgreSQL 运行代码
- 清除了“数据库迁移已接入”的误导性信号

### 2.2 删除 Python 构建生成物

已删除：

- `openclaw_guard.egg-info/`

删除原因：

- 属于构建元数据，不属于源码
- 应由打包或安装命令按需生成
- 长期保留在仓库中会污染结构判断

### 2.3 删除文档站构建残留文件

已删除：

- `docs/.vuepress/config.bundled_*.mjs`

删除原因：

- 属于 VuePress 构建时生成产物
- 不应作为源码长期保留

### 2.4 增补忽略规则

已更新：

- `.gitignore`

新增规则：

- `*.egg-info/`
- `docs/.vuepress/config.bundled_*.mjs`

目的：

- 避免构建产物再次进入项目目录
- 降低误提交与误分析概率

## 5. 结构风险与优化建议

### 5.1 高优先级

- 拆分 `manager.py`
  - 现状：既做编排，又做状态聚合，还承担部分领域与适配判断
  - 建议：拆成 `services/` 或 `application/` 子层

- 统一 Hook 术语
  - 现状：部分文档仍沿用旧事件名
  - 建议：统一以“当前运行时事件 + Guard 兼容 API 名称”表述

- 显式声明 Python 依赖
  - 现状：`pyproject.toml` 只声明了包信息，没有运行依赖
  - 建议：按“必需依赖 / 可选依赖”分组补齐

### 5.2 中优先级

- 规范实验区命名
  - 将 `testlab/实验准备`、`实验方案`、`实验结果` 统一为可枚举的中英文命名规则

- 归并文档草稿
  - 将研究笔记、架构草图、功能文档分层

- 统一目录命名风格
  - 当前存在：
    - 英文目录
    - 中文目录
    - 中英混合目录
  - 建议后续统一为“目录英文、文档标题中文”的方式

本次不是“大搬家式重构”，而是一次偏稳健的结构治理，重点完成了三件事：

- 清掉会误导维护者判断的遗留与生成文件
- 补齐可直接交付的项目分析与结构文档
