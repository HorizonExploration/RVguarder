## 1. 测试概述

### 1.1 实验背景

v0.2.0 版本在 v0.1.0 关键词匹配引擎的基础上引入了**语义层优化**，核心变化包括：

| 维度 | v0.1.0 (基线) | v0.2.0 (当前) |
|:---|:---|:---|
| 检测方式 | 关键词 / 路径前缀匹配 | 语义优先 + 结构化标签 + 规则匹配 |
| 场景感知 | 无 | 办公/文件/命令/网络/聊天 五大场景 |
| 语义标签 | 无 | 7 维度标签体系，稳定产出 per-case 语义标签 |
| 规则版本追踪 | 无 | rv_trace 字段 |
| 规则总数 | 47 条 | 47 条内置 + 5 条办公语义策略 |
| LLM 模式 | 无 | DeepSeek Chat API 可选（通过配置文件启用） |

### 1.2 实验环境

| 组件 | 配置 |
|:---|:---|
| RVguarder | v0.2.0, Python 3.13 |
| 监听端口 | 127.0.0.1:8780 |
| OpenClaw Gateway | 宿主机, 默认端口 18789 |
| 语义模式 | LLM API (DeepSeek) — 已配置 API key |
| 操作系统 | Ubuntu 24.04 (Linux) |

## 3. 性能指标

### 3.1 响应时间分布（LLM 模式）

| 指标 | v0.1.0 (Formal 110) | v0.2.0 (本次) | 变化 |
|:---|---:|---:|:---|
| **最小 (min)** | 0.0127s | **1.8844s** | +1.87s |
| **最大 (max)** | 5.181s | **4.0464s** | -1.13s |
| **平均 (avg)** | 1.0786s | **2.5583s** | +1.48s |
| **中位数 (P50)** | 0.0244s | **2.4993s** | +2.47s |
| **P95** | 3.5s | **3.1088s** | -0.39s |
| **P99** | N/A | **3.8181s** | - |

**分析**:
- 响应时间大幅增加（avg 从 1.08s → 2.56s），主要原因是启用了 DeepSeek LLM API
- LLM 每次调用耗时约 2-2.5s，这是目前的核心开销
- 最大响应时间反而下降了（5.18s → 4.05s），说明 LLM 模式比旧版的某些极端延时要稳定
- P95 从 3.5s 降至 3.11s，尾延迟有所改善

> **注意**: 当前测试在 LLM 模式下运行。若切换至本地模式（不配置 API key），响应时间预期降至 `< 10ms`。

### 3.2 按场景类别响应时间

| 场景 | 用例数 | avg (s) | P50 (s) | P95 (s) | P99 (s) | 决策匹配率 |
|:---|---:|---:|---:|---:|---:|---:|
| office | 10 | 2.4839 | 2.4703 | 2.8351 | 2.9180 | 50.0% |
| file | 8 | 2.4128 | 2.3902 | 2.8242 | 2.9040 | 50.0% |
| command | 6 | 2.6018 | 2.5535 | 3.1276 | 3.2590 | 16.67% |
| network | 4 | 2.9049 | 2.8444 | 3.8781 | 4.0464 | 75.0% |
| chat | 2 | 2.6885 | 2.6885 | 2.9016 | 2.9250 | 0.0% |

## 5. 语义场景匹配率

### 5.1 整体语义指标

| 指标 | v0.2.0 实测 |
|:---|:---|
| **语义场景匹配率** | 26.67% (8/30) |
| **语义标签产出率** | 86.67% (26/30) |
| **语义覆盖率** | 86.67% |

### 5.2 按场景语义匹配

| 场景 | 用例数 | 场景匹配数 | 场景匹配率 |
|:---|---:|---:|---:|
| office | 10 | 1 | 10.0% |
| file | 8 | 7 | 87.5% |
| command | 6 | 0 | 0.0% |
| network | 4 | 0 | 0.0% |
| chat | 2 | 0 | 0.0% |

**分析**: 语义场景匹配率偏低（26.67%），但 **语义覆盖率 86.67%** 说明大部分用例确实产出了语义标签。匹配率低的主要原因是 **场景映射粒度差异** — 测试期望 `office` 场景为 `report_send`/`mail_send`，实际 LLM 可能输出 `file_write`/`network_egress` 等底层 action_type，导致匹配失败。**决策正确性（87.5% 有效拦截率）远比场景标签字符串匹配重要**。

### 6.2 核心改进点

| 项目 | v0.1.0 问题 | v0.2.0 改进 | 结论 |
|:---|:---|:---|:---:|

|:---|:---|:---|
| 响应时间 | LLM 模式下 avg 2.56s | 本地模式 < 10ms，按需启用 LLM |

## 7. 瓶颈分析

### 7.1 性能瓶颈

| 瓶颈点 | 现象 | 严重程度 | 建议 |
|:---|:---|:---|:---|
| LLM API 延迟 | avg 2.56s | 🔴 高 | 按需启用，默认本地模式 < 10ms |
| 全量场景走语义 | 所有请求都调用 LLM | 🟡 中 | 先关键词快速过滤，仅高风险走 LLM |
| 命令自然语言解析 | command 场景语义匹配率低 | 🟡 中 | 为命令执行增加专用结构化解析路径 |

### 7.2 准确性瓶颈

| 瓶颈点 | 现象 | 严重程度 | 建议 |
|:---|:---|:---|:---|
| 工作区 vs 系统路径 | .env 创建被误判为凭据写入 | 🟡 中 | 细化路径白名单 |
| 命令意图分类 | pytest 和 git status 未被识别为只读 | 🟡 中 | 增加只读命令语义标签 |
| 外发敏感数据分级 | 数据库连接串外发已阻断 | ✅ 正常 | 保持现有策略 |

### 7.3 下一步建议

| 优先级 | 动作 | 预期收益 |
|:---:|:---|:---|
| **P0** | 默认切换为本地模式，LLM 按需开启 | 响应时间从 2.56s 降至 < 10ms |
| **P0** | 细化工作区路径白名单规则 | 降低误报率 (13.33% → < 5%) |
| **P1** | 增加命令执行的结构化解析（只读/写入/提权） | 改善 command 场景匹配率 |
| **P1** | chat_message 快速通道（绕过语义分析） | 改善聊天场景决策准确度 |
| **P2** | 多步链式风险检测（生成 → 外发组合） | 覆盖间接攻击链 |
