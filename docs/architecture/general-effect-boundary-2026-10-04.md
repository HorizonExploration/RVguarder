# 未知攻击的操作效果边界（2026-10-04）

## 处理原则

用户选择：高风险操作的授权不明确时，请求 OpenClaw 原生审批，尽量保留正常任务。通用约束按工具的操作效果执行，不能要求用户先提供完整攻击链。

现有 PMKB 已将未知工具、外发、文件写入、任务创建和配置变更纳入审批；已确认的严重违规仍可硬阻断。RV 继续根据成功执行历史提升风险，不能降低 PMKB 裁决。审批请求由 Guard 返回，批准或拒绝仍由 OpenClaw 原生入口处理。

## 发现与修复

| 缺陷 | 风险 | 本次修复 |
| --- | --- | --- |
| TraceCompiler 使用 setdefault 合并安全分类 | 工具参数的 `command_safety=read_only` 可覆盖本地证据 | 根据实际命令重新分类，覆盖派生 action_type、command、argv，不接受调用者的安全标签 |
| 只按命令名识别只读操作 | sed 脚本、搜索预处理器、输出选项、Git 分支修改可被自动放行 | 按操作效果识别执行、写入及未知脚本，转入审批 |
| 忽略命令来源和部分 shell 结构 | 工作区同名程序、环境赋值、多行和后台操作可能获得只读分类 | 未验证的程序路径及 shell 结构转入审批 |

这不是新增攻击链模板；同一约束可用于附件注入、直接工具调用或不同步骤组合中的危险动作。

## 验证

新增 `tests/test_command_effect_boundary.py`：19 种风险命令分别验证分类和执行前 Hook 审批；7 种常见只读命令验证分类保留；1 项验证工具参数和 metadata 都不能伪造安全分类；6 类非命令操作验证无需预设攻击链即可请求审批。共 52 项通过。

与已有日常策略和授权 Trace 测试合跑：首轮 63 项通过。首次修复前同组新增用例有 36 项失败、10 项通过，证实存在可重复的误放行。测试不执行攻击命令，不调用付费模型，也不替代 Docker 中的真实原生审批验证。

完整回归：673 项通过、19 项跳过、4 项子测试通过（137.34 秒）；该次收集发生在最后 6 项跨流程用例加入之前，新增 52 项随后独立全部通过。`git diff --check` 通过。

## 边界与后续验证

- 结果证明这些操作边界有效，不能推出“大多数未知攻击”的覆盖率；新增用例属于开发回归，不能算冻结 holdout。
- 正常但无法验证的脚本、环境变量展开及部分 Git/文本处理用法会新增审批，需要在正常办公任务中测量成本。
- 命令分类不是 shell 沙箱；它没有证明 PATH、系统二进制、Git 配置或搜索工具配置可信。可信执行环境和原生沙箱仍是前提。
- 外发数据的真实血缘、不同接收方的授权绑定和长时间跨会话证据需独立验证，不能仅凭调用名或附件的自述授权认定安全。
- 保留仓库规定的后端故障透传。因此后端不可用时，这些检查不构成防护保证。
- 下一阶段应冻结按机制隔离的新攻击和合法对照，记录实际副作用、原生审批次数、完成率及调用级规则证据，再评价未知链路泛化。
