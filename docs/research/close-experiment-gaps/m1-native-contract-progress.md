# M1 原生执行契约进展（2026-10-06）

## 已取得的证据

WSL 原生 Docker API 已恢复（29.8.0）。本轮使用 OpenClaw 2026.9.5、Node 24.19.0、隔离的临时 profile 与 Docker 沙箱执行一次公开资料调用链：原生 read → message send → network post → document share。模型响应来自本地冻结 provider，没有付费 API 调用。

[实际原生记录](m1-native-snapshot-contract.json)的四项内容检查均通过：原生准入、三个实际办公收据、三个消费哈希与公开资料一致、实际工具集合一致。办公副作用仍只写本地 JSONL，未发送真实消息或网络请求。执行器开启 snapshot-v1，签名及授权 checker 未开启。

这些结果验证执行契约，不增加攻击/正常任务实验分母，也不代表 Q5 或 M1 已通过。实际原生检查在本轮最终配置冲突修复之前运行；最新冲突边界由本地 Node 和独立复核验证，尚未作为新的原生签名验收。

## 失败与修复

- 首次运行清理 root-owned 目录时抛异常，未保存结果；不能计为成功。
- 第二次先保存实际结果，内容四项通过，但首次自动归属修复缺少 DAC_OVERRIDE，清理失败。原报告的整体 `passed=false` 保留。
- 两次明确归属的临时容器及工作区随后已清理，另存[恢复记录](m1-native-cleanup-recovery.json)，没有重跑工具链以替换失败记录。
- 原驱动按 profile 名匹配容器，而 SDK 按 workspace hash 命名。现在只删除运行后新建且宿主挂载路径精确属于本隔离 profile 的容器；保留已有容器与相近 profile。
- 相同配置的重复 SDK 注册现在共享一个一次性消费快照及证明接口；最后一个注册表停止才释放。不同配置一律拒绝，包括无签名与 legacy 执行器，防止 A 的证明对应 B 的实际字节。
- before 快照准备优先级设为 100。Node 测试夹具现在执行 gateway_stop 并删除临时目录，避免跨测试配置泄漏。
