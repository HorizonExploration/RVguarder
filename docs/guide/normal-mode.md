# normal 简洁模式

## 它解决什么问题

很多用户并不是安全工程师，他们只想：

- 能直接和 OpenClaw 交互
- 在危险操作发生前得到明确确认
- 不想先看一堆策略、规则、JSON 和后台卡片

`normal` 模式就是为此设计的。

## 启动命令

```bash
python -m openclaw_guard.main normal
```

## normal 模式的特点

- 首页默认就是对话界面
- 导航更少，只保留最常用入口
- 自动补齐基线结果，不要求用户先手动扫描
- 提示文案更偏“人话”，避免安全工程黑话
- 危险动作仍然会被拦住，但专业细节放到设置页

## 适合哪些人

- 初次接触 OpenClaw 的普通用户
- 只需要聊天、提任务、审批危险操作的使用者
- 不需要频繁查看规则链、审计详情和内部能力状态的值守人员

## 不适合哪些场景

- 策略规则调试
- 高级审计分析
- 需要观察大量技术细节的测试环境

这类场景建议使用完整模式：

```bash
python -m openclaw_guard.main launch
```

## 与完整模式的区别

| 项目 | normal 模式 | launch 完整模式 |
| --- | --- | --- |
| 默认首页 | 对话 | 工作台 |
| 导航复杂度 | 更少 | 更完整 |
| 安全细节展示 | 收敛到设置页 | 全量可见 |
| 适用对象 | 普通用户 | 开发 / 运维 / 策略人员 |

## 使用建议

如果你的目标是“稳定使用而不是调系统”，优先用 normal。
