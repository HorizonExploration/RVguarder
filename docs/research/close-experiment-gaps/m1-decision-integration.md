# M1 下一步：受控内容授权接入有限调用规约

## 前提与可验收结果

当前资源观察、宿主授权、认证成功回调、签名收据和内容关系查询已实现；后台证据尚不改变裁决。下一步须取得公开摘要及 v4 N03 实际完成收据，同时保留冻结 17 例防护集合，才可判定 M1 通过。下述内容为接入设计，未实现部分不作为现有能力。

## 1. 冻结可信执行契约

局部实现进展见[执行快照](m1-execution-snapshot.md)：可选固定字节已通过本地工具检查，执行前可信证明、完整原生身份与同步 I/O预算尚未验收。本节完整前提仍未达成。

[签名执行前证明](m1-execution-proposals.md)现已实现并进入后台诊断，不能用于授权放行；真实部署身份/密钥隔离、时效边界及同步准备预算仍待验收。

- 先验证实际 OpenClaw 中三个办公工具的 SDK 调用关联、可信执行器与 Agent 容器隔离。Agent 不得读取签名密钥、写授权库或替换执行器配置；也不得通过宿主 exec 绕过边界。
- 只有已登记的具体工具和精确有限效果可参与授权；多功能工具的未知子动作不能获得工具名级授权。
- 外发使用经过授权的确定资源版本，执行器强制核验消费字节。遗漏约束、换内容或缺失文件先于副作用失败。B0/Guard 使用相同执行器及原生配置。
- 原生 read/write 的内容证据需独立适配；结果摘要、文件路径或旁路读取不能代替实际消费/产生字节。无法等价提供时显式排除相关比较，不伪造血缘。

## 2. 有界取得当前宿主授权

任务只由宿主活动记录与认证 SDK 上下文关联；任务、主体、Agent、session/run、资源版本、操作、接收方、TTL、撤销必须同时成立。参数、附件、模型和 `raw_user_intent` 不签发授权。

接入须解决撤销可见性与版本执行竞态。现有异步 `reference_grant_match` 只是诊断，不能直接放行；不可为此在 before Hook 无界等待文件/数据库。未知、歧义、超时或过期均保持不确定，不假定授权。先证明身份、内容消费和时效边界，再启用放行分支。

## 3. 让 DSL 消费可信类型事实

一实际调用仍为一 `tool-call-v1` 事件。资源与授权事实补充该事件，不新增合成 read/send，也不让 LLM 推导动作效果。

授权约束应是由服务端构造的类型化字段，不能是模型可生成的 `props` 标签。拟新增资源/授权守卫，并在需要资源关联的外发规则中逐条限定适用范围：

接口已实现，见[逐规则守卫](m1-dsl-authorization-guard.md)；默认checker为None，现有诊断尚未准予作为可裁决事实，以下完整行为尚未通过真实阶段验收。

| 已核实条件 | 预期处理 |
| --- | --- |
| 无授权的敏感内容外发，且真实成功历史与当前消费资源关联成立 | RV 独立 block |
| 高风险，授权或内容关联仍不明确 | 原生 ask，记录不确定来源 |
| 精确宿主授权与消费版本成立 | 当前相关 RV 条件不触发，沿 PMKB 单步策略 |
| 其他 RV 规则或 PMKB 已有硬约束成立 | 保留 block |

不得设置全局 RV 降级门，不得由一个授权抑制所有监视器，也不降低 PMKB 已有 block。具体规则变更后记录新哈希；保持旧成果原样，已见场景均为 calibration。

## 4. 一次阶段级验收

先跑相关单元/契约测试，规则和执行器稳定后，合并做一次 Docker M1 验收：近邻攻击/公开摘要、v4 N03及授权反例、17 例已防护集合和紧邻正常对照。预先固定审批表与两个 Oracle；保留首次失败，不以重试改写。按 R1/R3/R4/R5分别判定，之后才进入 M2和新的冻结评估。

新增关系组合测试只证明可连接内容来源，不能宣称已防住未知攻击或多数链路。效果仍由实际副作用/完成收据判定，审批和延迟由实际原生边界测量。
